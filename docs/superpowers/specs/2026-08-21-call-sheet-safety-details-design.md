# 拍摄通告现场保障信息设计

## 目标

让每个拍摄日可维护天气与雨天预案、安全提示及紧急联系人，并确保这些信息在拍摄通告的编辑、发布快照、打印单与 Excel 中一致。

## 数据模型与迁移

在 `public.shoot_days` 新增六个非空文本列，默认空字符串：

- `weather`
- `rain_plan`
- `safety_notes`
- `emergency_contact_name`
- `emergency_contact_role`
- `emergency_contact_phone`

使用一份新的增量迁移，不修改已部署迁移。领域 `ShootDay` 和创建输入同步扩展；现有拍摄日与旧数据库记录通过默认空字符串兼容。

## 数据流

Supabase 网关在拍摄日的读取、创建与更新操作中映射六个字段；假网关保持相同对象形状。通告页使用现有的拍摄日更新回调保存“现场保障”表单。`buildCallSheetSnapshot` 已完整复制拍摄日对象，因此发布版本自动冻结这组字段；已有的未发布变更比较也会检测它们。

## 展示与交付

通告页在“通告制作资料”之后呈现“现场保障”表单。拍摄日打印单和 Excel 信息页仅在对应值已填写时展示天气、雨天预案、安全提示及紧急联系人，避免为空的占位信息干扰现场阅读。

## 错误处理与兼容性

保存失败沿用现有工作台的保存状态和重新加载行为。若远端尚未执行新迁移，网关会按既有拍摄日模式报告错误；本次不改变现有行级安全策略。

## 测试

先添加失败测试，再做最小实现：

1. 通告页保存现场保障字段，并将其传给拍摄日更新回调。
2. 通告快照和未发布变更状态包含现场保障字段。
3. 假网关保存并读取现场保障字段。
4. Supabase 网关的查询与写入包含新列。
5. 打印单与 Excel 信息页在有值时输出保障信息、空值时不输出。
