# 分镜平台功能一致性验收设计

## 目标

验证所有已发现分支与工作区的分镜平台功能是否和实现一致；将已验证功能集中到唯一集成分支，并修复可复现的不一致。

## 范围与边界

验收对象为 `agent/next-optimization`、`agent/add-storyboard-saas-design`、冻结的 `8f32e27` 工作区提交，以及 `integration/storyboard-platform`。原分支、旧工作区和生产数据库不被重置、清理或覆盖。在线 Supabase 状态单列为“需在线验证”，不以代码文件代替实际执行证据。

## 验收矩阵

每个来源运行锁定依赖下的 `pnpm test --run` 与 `pnpm build`，并检查：项目/模板、字段和个人视图、镜头与图片/参考图、场景/审核、拍摄计划/通告单、Excel/PDF 导出、权限和迁移。集成分支对同一矩阵重复测试；分支实现但集成缺失的功能通过 Git 合并或最小补丁接收。

## 修复策略

每个差异先记录复现步骤和期望行为，再添加会失败的自动化测试。仅在集成工作区实现最小修复；完成后运行定向测试、全量测试和生产构建。冲突文件必须保留两条分支各自已验证的行为，不能以选择一侧版本替代另一侧。

## 交付物

- 每个来源的命令测试与构建结果。
- 功能一致性矩阵：已实现、缺失、冲突已解决、需线上验证。
- Supabase 迁移账本及其已知在线状态。
- 一个通过全量验证的集成分支；部署只从该分支进行。
