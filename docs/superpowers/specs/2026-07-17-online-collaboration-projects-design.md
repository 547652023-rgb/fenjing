# 在线多项目与实时协作设计

## 目标

将现有只在单台电脑浏览器中保存一个项目的分镜工作台，升级为支持账号登录、多个在线项目、成员邀请和多人实时编辑的应用，同时完成镜头排序/删除、景别固定选项和项目级自定义下拉菜单。

## 范围

本轮包含：

- 邮箱密码注册、登录和退出。
- 在线项目的新建、进入、重命名和删除。
- 所有者按注册邮箱邀请成员共同编辑。
- 项目、字段、镜头和图片的在线保存与实时同步。
- 镜头拖拽排序、按钮上移/下移、删除和连续自动编号。
- 景别固定初始选项，以及其他字段的项目级自定义下拉选项。
- 原有本机单项目数据的一次性导入。
- GitHub Pages 的构建和发布兼容。

本轮不包含复杂组织架构、项目角色自定义、审计日志、版本历史恢复、逐字符协同编辑或离线优先编辑。

## 技术方案

采用 Supabase 托管后端，前端继续使用现有 React、TypeScript、Vite 和 GitHub Pages。

Supabase 负责：

- Auth：邮箱密码注册、登录和会话。
- PostgreSQL：项目、成员、字段、选项和镜头数据。
- Storage：分镜画面和参考图片。
- Realtime：项目内数据变更通知和在线同步。
- Row Level Security（RLS）：限制用户只能访问自己拥有或参与的项目。

浏览器只配置 Supabase 项目 URL 和可公开的客户端密钥。管理员密钥不得进入前端代码、GitHub 仓库或 GitHub Pages 构建产物。

## 页面与导航

### 登录页

- 未登录用户只能看到注册和登录界面。
- 支持邮箱密码注册、登录和退出。
- 清楚显示邮箱格式、密码、验证邮件、账号不存在或网络失败等中文提示。

### 项目首页

- 登录后默认进入项目首页。
- 分区或标识展示“我创建的项目”和“受邀项目”。
- 项目卡片显示名称、所有者、成员数量和最后更新时间。
- 支持新建、点击进入和重命名。
- 只有所有者能删除整个项目，删除前二次确认。
- 受邀成员可以进入和编辑，但不能删除项目或管理成员。

### 分镜工作台

- 顶部提供返回项目首页、成员管理、字段设置、保存/网络状态和退出入口。
- 保留现有字段显示隐藏、新增字段、五张画面图片和一张参考图片能力。
- 项目标题、字段、选项、镜头和图片改为在线保存。

## 权限模型

- 每个项目有且仅有一个所有者。
- 项目成员分为 `owner` 和 `editor`。
- 所有者可以编辑项目、管理成员和删除项目。
- 编辑者可以读取和编辑项目、字段、选项、镜头和图片。
- 只有项目成员可以订阅该项目的实时频道或读取其私有图片。
- 邀请使用已注册邮箱。邮箱尚未注册时，界面提示对方注册后才能加入，本轮不发送邀请邮件。
- RLS 是最终权限边界；前端隐藏按钮只用于改善体验，不能代替数据库权限校验。

## 数据模型

建议使用以下关系表：

- `profiles`：用户 id、邮箱展示信息、创建时间。
- `projects`：id、标题、所有者 id、创建时间、更新时间。
- `project_members`：项目 id、用户 id、角色、加入时间；项目和用户组合唯一。
- `fields`：id、项目 id、字段键、名称、类型、是否显示、排序位置。
- `field_options`：id、字段 id、选项值、排序位置。
- `shots`：id、项目 id、排序位置、字段值 JSON、版本号、创建时间、更新时间。
- Storage 私有 bucket：按 `project-id/shot-id/field-id/file-id` 保存图片。

字段值继续使用 JSON，便于保留用户自行新增字段的灵活性；字段定义和下拉选项独立成表，便于排序、权限控制和实时同步。

每条可并发编辑记录带版本号或更新时间。更新时携带旧版本条件，服务器拒绝过期写入，前端随后拉取新数据并提示用户，而不是静默覆盖。

## 项目数据迁移

- 登录后检测旧版 `localStorage` 单项目数据。
- 若检测到旧数据且尚未迁移，显示“导入本机项目”提示。
- 只有用户确认后才创建在线项目并上传数据和图片。
- 导入成功后记录迁移完成标记，但不立即删除旧数据，避免误丢失。
- 导入失败时保留旧数据，并说明失败阶段和重试方式。

## 镜头排序与删除

- 表格最左侧新增固定的操作列。
- 每行显示拖拽手柄、上移、下移和删除。
- 拖拽可以移动到任意位置；按钮每次移动一行，可连续操作。
- 第一行禁用上移，最后一行禁用下移。
- 删除镜头必须二次确认。
- 新增镜头追加到末尾。
- 新增、移动或删除后，根据当前顺序自动把镜号重排为 `1, 2, 3...`。
- 排序位置使用可重排值，最终由事务或数据库函数原子更新，避免多人同时排序产生重复位置。
- 实时事件到达后以服务器顺序为准刷新列表。

## 景别与自定义下拉菜单

### 景别

景别默认是单选下拉字段，预置并限制为：

1. 大远景
2. 远景
3. 全景
4. 中景
5. 近景
6. 特写

### 其他字段

- 每个项目可以在字段设置中把时长、内容、备注等非图片字段改为带选项的下拉输入。
- 项目成员可以新增、修改、删除和排序字段选项。
- 单元格提供可搜索的下拉菜单，同时允许输入选项之外的临时内容。
- 临时内容只保存到当前单元格，不自动加入字段选项列表。
- 字段选项随项目在线保存，并实时同步给所有项目成员。
- 图片字段不支持转换为文本下拉菜单。

## 图片存储

- 画面列每个镜头最多五张图片，参考列最多一张。
- 新图片直接上传到项目的私有 Storage 路径，数据库只保存对象路径、顺序和必要元数据，不保存 base64 图片正文。
- 前端通过有权限的请求或短时签名地址显示图片。
- 删除图片时同步删除数据库引用和存储对象；若其中一步失败，记录可重试状态，避免界面误报完全成功。
- 上传中显示逐张进度，失败图片可单独重试。

## 实时同步与冲突

- 进入项目后订阅该项目的私有实时频道。
- 项目标题、成员、字段、选项和镜头的新增、修改、删除会推送到其他在线成员。
- 不同单元格的修改可以独立保存。
- 同一记录的并发修改使用版本检查。最后一次合法写入生效，收到冲突的一方重新读取服务器值，并看到“内容已被其他成员更新”的提示。
- 若某成员正在编辑的镜头被他人删除，本地编辑立即失效，不允许把已删除镜头重新写回。
- 本轮实时粒度是单元格提交后的数据同步，不实现类似在线文档的逐字符合并和远程光标。

## 网络与错误处理

- 顶部状态区显示正在保存、已保存、离线、重连中和保存失败。
- 网络断开时保留当前输入草稿，但不宣称已保存。
- 恢复连接后先重新读取服务器状态，再尝试提交仍然有效的本地改动。
- 无权限、登录失效、保存失败、上传失败、实时连接失败和数据冲突均提供中文提示。
- 登录失效时返回登录页；登录恢复后回到项目首页，不泄露之前项目数据。
- 删除项目、删除镜头、移除成员等不可逆操作都需要确认。

## 组件边界

- `AuthGate`：会话初始化与登录状态切换。
- `AuthScreen`：注册和登录表单。
- `ProjectDashboard`：项目查询、卡片列表和项目级操作。
- `ProjectWorkbench`：当前项目加载、实时订阅和工作台页面状态。
- `MemberManager`：成员查询、邀请和移除。
- `FieldSettings`：字段和下拉选项设置。
- `StoryboardTable`：镜头显示、编辑、拖拽和按钮操作。
- `ImageCell`：在线图片上传、删除、顺序和状态。
- 数据访问层：封装 Supabase 查询、上传、订阅与错误映射，不让 UI 组件直接拼接数据库请求。

## 测试与验收

### 自动化测试

- 账号状态和权限控制的组件测试。
- 多项目新建、重命名、删除和进入流程测试。
- 所有者与编辑者权限差异测试。
- 镜头新增、拖拽、按钮移动、删除和自动编号的领域测试。
- 景别六项限制测试。
- 项目级下拉选项管理、选择和临时输入测试。
- 五张画面图片限制和一张参考图片限制测试。
- 数据访问层的成功、失败、冲突和重连测试。
- 旧本机项目迁移测试。

### 集成与人工验收

- 两个账号同时打开同一项目，一端修改后另一端自动更新。
- 两端同时编辑同一记录时出现明确冲突提示且不静默丢数据。
- 非成员无法通过直接项目地址读取项目和图片。
- 编辑者无法删除项目或管理成员。
- 网络中断和恢复后状态正确，服务器已有修改不被过期输入覆盖。
- GitHub Pages 构建成功，刷新和返回流程可用。

## 部署前置条件

实施需要创建一个 Supabase 项目，并取得项目 URL 和客户端公开密钥。还需要执行仓库内提供的数据库迁移 SQL、创建私有图片 bucket、配置邮箱登录和 GitHub Pages 允许的站点地址。以上配置完成前，前端可以使用测试替身完成大部分开发和自动化验证，但无法完成真实账号、实时同步和私有图片的最终在线验收。
