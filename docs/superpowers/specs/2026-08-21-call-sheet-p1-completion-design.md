# 拍摄通告 P1 收口设计

**日期：** 2026-08-21  
**范围：** 拍摄通告成员确认回执、执行清单视图、临期页内提醒、正式版本打印。

## 目标与边界

P1 为已发布的拍摄通告补齐执行闭环：项目成员能确认自己已阅读某一发布版本；全体项目成员可看到确认进度；拍摄临近时，通告页提示尚未确认人数；负责人可打印固定版本而不是会继续变化的草稿。

本轮不做站内通知中心、短信、邮件、企业微信或其他外部推送；不新增部门或镜头负责人字段。执行清单仅使用已有的场次和现场状态数据进行分组与筛选。

## 数据与权限

新增 `call_sheet_acknowledgements`：

| 字段 | 含义 |
| --- | --- |
| `call_sheet_version_id` | 已发布通告版本 ID |
| `user_id` | 确认成员 ID |
| `acknowledged_at` | 确认时间 |

`(call_sheet_version_id, user_id)` 唯一，因此同一成员对一个版本最多确认一次。历史记录不因发布新版本或撤销通告而删除；撤销版本不能再新增确认。RLS 以通告版本所属项目的成员关系为边界：成员可读取本项目回执，只能插入自己的回执。

`CallSheetVersion` 保持原有版本快照及撤销语义。网关新增按版本列出回执与确认版本的接口；假网关、Supabase 网关、工作台都实现相同契约。发布、切换拍摄日或完成确认后刷新当前版本的回执。

## 通告页行为

当前未撤销发布版本下增加“成员确认”区域：显示成员总数、已确认数、未确认数、成员邮箱和确认时间。尚未确认的当前登录成员看到“确认已阅读 Vn”按钮；请求执行时防止重复提交，失败显示中文错误并保留当前界面状态。

临期提醒为纯前端计算：仅当当前版本未撤销、拍摄日期在今天起三天内且仍有成员未确认时展示，文案指出拍摄日与未确认人数。它不产生后台任务或外部消息。

镜头执行清单保留拍摄顺序和既有现场状态回写，增加“按场次 / 按现场状态”视图切换：默认按场次；状态视图按既有生产状态分组。没有场次的镜头归入“未分配场次”。

## 正式打印

新增通告正式打印视图，只能从当前未撤销的发布版本快照打开。视图使用快照中的项目名称、拍摄日、场次与镜头，页头明确显示版本号和发布日期，避免把草稿表示为正式通告；展示制作资料、现场保障、按场次镜头表及回执概览。打印时调用浏览器打印；关闭不修改数据。

已有拍摄日打印继续可用于草稿，不替代正式版本打印。

## 错误处理与验证

网关将未登录、无权、版本不存在、版本已撤销和网络错误映射为现有中文错误路径。确认接口幂等：重复确认返回既有记录，而不是产生重复行。

测试先覆盖：假网关的唯一确认/撤销限制；Supabase 查询与写入；通告页确认、临期提示、两种镜头分组；正式打印仅使用已发布快照及回执概览。实现完成后运行完整测试套件、生产构建与 `git diff --check`，再提交并推送。

## 非目标

- 外部通知、提醒排程和通知中心。
- 部门、镜头负责人、演员或设备的新增数据模型。
- 对 `integration/storyboard-platform` 的任何直接修改或合并。
