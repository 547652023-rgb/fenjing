# 画面列单行多图设计

## 目标

允许每个分镜行的“画面”单元格保存和展示最多 5 张图片。用户既可以一次选择多张图片，也可以分多次继续添加。图片在同一单元格内横向排列，并拉伸铺满各自的缩略框。

“参考”列继续保持现有的单图行为。本次不增加图片排序、云端上传或多人同步功能。

## 数据兼容

现有 `Shot.values` 仍保持 `Record<string, string>`，避免扩大项目数据结构的迁移范围。

- “画面”字段使用 JSON 字符串保存图片 data URL 数组。
- 旧项目中已有的单个 data URL 自动解释为只含一张图片的数组。
- 空字符串解释为空数组。
- 无法解析的非空旧值按单张图片处理，避免静默丢失已有内容。
- 保存新值时，画面字段统一写回 JSON 数组；参考字段仍写回单个字符串。

## 交互设计

“画面”单元格展示一个横向图片条：

- 每张图片显示在固定尺寸缩略框内，使用拉伸铺满效果，不保持原始宽高比。
- 每张图片提供独立的“移除”按钮。
- 未达到 5 张时显示“添加图片”入口。
- 文件选择器允许一次选择多张图片，并支持后续继续添加。
- 一次选择超过剩余名额时，仅接收按选择顺序排列的前几张，并显示“每行最多 5 张图片”的提示。
- 非图片文件不读取，并显示“请选择图片文件”的提示。
- 达到 5 张后不再显示添加入口，并显示 `5/5` 数量状态。

图片顺序按添加顺序保存。本次不提供拖拽排序。

## 组件边界

`ImageCell` 扩展为可配置的图片单元格：

- 接收字符串存储值、最大图片数和变更回调。
- 在组件边界解析旧单图值和新数组值。
- 负责文件校验、异步读取、数量限制、预览和单图删除。
- 对外仍通过字符串回调，保持 `StoryboardTable` 与项目存储层接口稳定。

`StoryboardTable` 对“画面”字段传入最大数量 5，对其他图片字段传入最大数量 1。这样“参考”列保持原行为，同时避免复制两套上传组件。

## 样式

- 多图容器使用横向 flex 布局。
- 单张缩略图使用固定宽高，`object-fit: fill`，满足允许拉伸变形的要求。
- 画面列最小宽度相应增加；整个分镜表格继续使用现有横向滚动容器。
- 删除按钮与添加入口保持键盘可访问，并为每张图片提供带序号的可访问名称。

## 错误处理

- 读取失败的文件不加入数组，并提示读取失败。
- 非图片文件不加入数组。
- 超过上限的图片不读取，避免不必要的内存占用。
- 多文件异步读取后仍按用户选择顺序写入。

## 测试

采用测试驱动开发，覆盖：

1. 一次上传多张图片并按顺序保存。
2. 在已有图片基础上继续追加。
3. 最多保存 5 张，超出的文件被忽略并提示。
4. 单独删除指定图片。
5. 旧单图 data URL 可以正常预览并升级为数组存储。
6. “参考”字段仍只允许一张图片。
7. 非图片文件和读取失败不会破坏现有图片。
8. 全量测试、TypeScript 检查和生产构建通过。

## 验收标准

- 每个分镜行的“画面”列可展示和保存 0～5 张图片。
- 支持一次多选和多次追加。
- 每张图片可独立删除。
- 图片在缩略框中拉伸铺满。
- 刷新页面后图片数量、顺序和内容保持不变。
- 旧项目的单张画面图片不会丢失。
- “参考”列行为没有变化。
